## Start in a new Codex session

1. Extract the ZIP fully and open the **inspro-production** folder in Codex.
2. Install a supported Node.js 24 LTS release if Node is unavailable. Node 22 is also supported; the release was verified locally with Node 22.18.0.
3. Ask Codex: **"Read AGENTS.md and README.md, run npm run check, then run npm run dev and open http://127.0.0.1:3000. Keep the server running."**

Or run these commands in the extracted folder:

```sh
npm run check
npm run dev
```

Open **http://127.0.0.1:3000** (localhost:3000 also normally resolves there). No `npm install` step is required. If PowerShell blocks `npm.ps1`, use `npm.cmd run dev`, or `node scripts/server.mjs --local` directly.

The local server is a process, so a new session or computer restart may require starting it again. The files do not depend on the old session. Opening index.html directly with file:// is unsupported because asset URLs start at the web root. The server resolves files relative to its own location, not an old Windows path.

If port 3000 is busy, stop only the server you own or choose another port. In PowerShell: `$env:PORT=3001; npm.cmd run dev`. On macOS/Linux: `PORT=3001 npm run dev`. Use that port in the browser.

## Editing the interactive components

The prebuilt website in `site/` remains ready to serve without `npm install`. For changes to React components or their rendered content, install the exact locked development dependencies with `npm ci`, run `npm run build:ui`, then `npm run redesign:pages` and `npm run check`. On restricted Windows profiles, use `npm.cmd ci --cache .impeccable/npm-cache`.

Component sources live in `src/`; `scripts/redesign-pages.mjs` contains the current page compositions and renders the components into HTML. That command replaces page body content, so carry deliberate direct HTML body edits into the composition script before regenerating. It retains existing page metadata and the protected homepage sections. Edit styling in `site/assets/css/experience.css`, colours in `tokens.css`, and scroll behavior in `site/assets/js/experience-motion.js`. Serving and ordinary validation do not execute the component build.

## Cloud deployment

The simplest supported route is static hosting on Netlify. Deploy **site/**, not the handover root. For a Git-connected deployment, the included netlify.toml uses `npm run build` and publishes `site`. Build is validation only; the source is already deployable. For manual upload, drag the **site** directory into Netlify's deploy interface. The included `_redirects`, `_headers` and `404.html` supply redirects, security headers and the error page.

For any Node-capable cloud host: build command `npm run build`, start command `npm start`, health path `/healthz`. The server uses `PORT` supplied by the host (3000 by default) and binds to `0.0.0.0`. There are no secrets or persistent volumes. Configure HTTPS at the cloud proxy and connect your domain there.

An optional Dockerfile is provided: `docker build -t inspro-site .`, then `docker run --rm -p 3000:3000 inspro-site`. See docs/VERIFICATION.md for whether the container itself was verified on the handover machine.

Other static hosts must be configured to support directory indexes, real 404 responses and the legacy redirects. `_headers` and `_redirects` are host-specific files, not universal web standards. This is a multi-page site: do not rewrite every missing URL to index.html.
